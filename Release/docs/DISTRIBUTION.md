# AmazingHelper 2.8.0: сборка и приёмка

Поставка: AmazingHelper.exe (Windows 10 1809+/11 x64, Python 3.12.8,
PyInstaller onedir), AmazingLawClient.dll/asi и AmazingHelperInjector.exe x86,
Inno Setup 7.1.1. Внешний оверлей и команды backend/manager/overlay/launcher/
install-browser сохранены. DLL/ASI — один модуль под разными именами.

## Сборка

Все Python-команды выполняются через `.venv/Scripts/python.exe`.
Создайте окружение Python 3.12.8, установите `requirements.txt`.
Для C++ требуются Visual Studio 2022 C++, ATL x86/x64, CMake и Windows SDK.
Локальная сборка при SDK в кеше также использует ATL из Visual Studio.

```
scripts\build\build_native.bat
powershell -File scripts/acquire_inno.ps1
.venv\Scripts\python.exe scripts/build_distribution.py --native-dir native/out/Release --iscc .cache/tools/inno/ISCC.exe --publish
```

При локальной сборке с кешированным SDK используйте `--native-dir native/out-local`.
Сборка проверяет версию помощника, создаёт манифест комплекта, проверяет frozen
режимы и создаёт `.cache/dist/AmazingHelper-2.8.0-portable-x64.zip` и Setup.
`--publish` также обновляет отслеживаемую Release, сохраняя личные файлы.

Blackbone закреплён на `5ede6ce50cd8ad34178bfa6cae05768ff6b3859b` (MIT).
Собирается только пользовательская библиотека; включение привилегий и открытие/
загрузка драйвера отключены в генерируемых исходниках. Флаги скрытия не используются.
Комплект включает лицензии Blackbone и вложенных зависимостей.

## Подпись и GitHub Releases

Публичный ключ в `amazing_overlay/update_public_key.txt`. Закрытый ключ —
base64 от 32 байтов Ed25519 в GitHub Actions secret `UPDATE_SIGNING_KEY`.
Закрытый ключ нельзя добавлять в Git, выводить в лог или помещать в артефакты.
Для нового проекта ключ создаётся однократно командой:

```
.venv\Scripts\python.exe scripts/release_metadata.py --generate-key .cache/secrets/update-signing-key.txt
```

Команда отказывается заменять существующий публичный ключ. Для текущей поставки
используется уже созданный ключ. После передачи ключа в GitHub Secrets храните
резервную копию закрытого ключа отдельно; ротация требует обновления доверенного ключа.

Тег `vX.Y.Z` должен совпадать с `amazing_overlay/version.json`. После успешных
проверок CI подписывает точные Setup/ZIP, публикует updates.json, updates.sig и
SHA256SUMS.txt. В PR секрет недоступен. Отсутствие или несовпадение ключа
останавливает публикацию. Authenticode у AmazingHelper пока отсутствует.

## Данные и обновление

Настройки, ключи, база и профиль: `%LOCALAPPDATA%/AmazingLawOverlay/v2`.
Notes установленной версии: Known Folder «Документы»/AmazingHelper/Notes;
явно выбранный путь имеет приоритет. На первом запуске можно подключить старую
Notes без переноса. Portable сохраняет Notes рядом с EXE, исходники — в корне.
Chromium загружается отдельно в существующий пользовательский кеш Playwright.

Установщик не содержит личных данных. Обновление проверяет подпись, размер и
SHA256 перед запуском Setup. Установщик и деинсталлятор требуют закрыть игру и
все режимы приложения у всех пользователей. Игра никогда не закрывается
принудительно. Не запускайте приложение до завершения установки.
Установщик заменяет только поставляемые файлы; незнакомые локальные файлы,
включая пользовательские подпапки внутри runtime, не удаляются. Прерванную
установку восстанавливают повторным запуском того же Setup.

## Матрица ручной приёмки

На отдельной повышенной тестовой Windows-сессии автоматизирована базовая приёмка:
`.venv/Scripts/python.exe scripts/check_installer.py --setup .cache/dist/AmazingHelperSetup.exe`.
Она использует только `.cache/installer-acceptance`, отказывается заменять другую
установку и проверяет установку, отказ при работающем бэкенде, repair повреждённого
runtime, удаление и повторную установку с сохранением синтетических ключей, базы и TXT.
Эта проверка также включена в GitHub Actions.

На Windows 10 x64 и Windows 11 x64 отдельно проверить:

- Чистую установку с UAC, ярлыки, запуск обычным пользователем без Python.
- Отмену UAC, отмену скачивания, отсутствие сети, недостаток места, повреждённый
  установщик и неверную подпись; действующая установка остаётся доступной.
- Обновление на новую версию, запрет при игре/клиенте другого пользователя,
  занятые файлы, прерывание установки и восстановление тем же Setup.
- Удаление и повторную установку; настройки, ключ, SQLite, история и Notes
  остаются. Проверить TXT UTF-8/BOM/CP1251 и CRLF, кириллическую учётную запись,
  перенаправленную папку Документы, две учётные записи.
- Отсутствие инъекции при открытии EXE, отсутствующей игре, отмене выбора;
  повторное нажатие и полный перезапуск игры.

Это чек-лист, а не заявление о выполненной проверке на обеих ОС. Фактически
выполненные проверки и ограничения фиксируются в PR.

## Собственный D3D9-стенд

`scripts/check_manual_map.py --native-dir native/out-local` запускает только
`overlay_native_smoke.exe --manual-map-host`, его вариант `overlay_native_smoke_dep_off.exe`
и тестовый загрузчик, который принимает исключительно эти два имени процесса.
Проверяются DEP-on и DEP-off, по два запуска рабочей DLL и TLS-фикстуры на каждый режим.
Производственный помощник принимает
только amazing.exe/gta_sa.exe. Стенд использует отдельные DATA/PIPE и не обращается
к игре. Проверяется регистрация готовности, работа RPC и отклонение дубля.
Рабочая DLL не содержит экспериментального `thread_local`: тест TLS и C++
исключений собирается отдельно в `tls-fixture` и не попадает в поставку.
Упаковщик отклоняет DLL с экспортом `AmazingOverlayTlsFixtureTag`.

Встроенный загрузчик использует `MemProtectionCasting::none`: права секций собственной
DLL сохраняются из PE и при отключённом DEP. Политика DEP процесса не меняется;
проверки исполняемых адресов MinHook сохранены. Настройка устраняет потерю
`PAGE_EXECUTE` из-за стандартного поведения Blackbone `useDep`.

Журнал `%LOCALAPPDATA%/AmazingLawOverlay/v2/launcher-lifecycle.log` фиксирует запуск,
состояние приложения, сообщения закрытия/смены дисплея и штатный выход лаунчера.
`launcher-fault.log` содержит стеки Python при нативном сбое. Содержимое заметок,
настройки, ключи и аргументы процессов в эти журналы не записываются.

**Совместимость с настоящей игрой и её защитой не подтверждена.** Стенд не
подтверждает игровой ввод, отсутствие АФК или допустимость по правилам сервера.
Дальнейшая игровая приёмка — по GAME_ACCEPTANCE.md.
